2.20. Сохранение
================

Всё, что хранится в переменных, пропадает, когда игрок закрывает игру. Рекорд,
открытые уровни, настройки громкости нужно записать в файл и прочитать при
следующем запуске.

.. in-game::

   Представьте, что игрок прошёл пять уровней, закрыл игру, а завтра открыл —
   и снова видит только первый. Больше он в эту игру играть не станет. Игра
   должна помнить прогресс.


Куда сохранять
--------------

Путь ``res://`` — папка проекта. После экспорта она упакована внутрь игры, и
писать в неё нельзя. Для данных игрока есть путь ``user://`` — отдельная папка
на компьютере игрока. В Windows она лежит в ``AppData`` пользователя, в браузере
данные хранятся в памяти браузера. В коде путь всегда начинается с
``user://``, а куда он ведёт, Godot решает сам.


ConfigFile
----------

Для настроек и простого прогресса удобен :godot:`ConfigFile` — текстовый файл из
разделов и пар «ключ = значение»:

.. code-block:: text

   [player]

   name="Герой"
   level=3

   [settings]

   volume=0.5

- :godot:`ConfigFile.set_value()` — записать значение: раздел, ключ, значение;
- :godot:`ConfigFile.save()` — сохранить в файл;
- :godot:`ConfigFile.load()` — прочитать файл. Возвращает код ошибки: ``OK``, если
  всё прочиталось;
- :godot:`ConfigFile.get_value()` — получить значение. Третий аргумент —
  значение по умолчанию, если такого ключа нет.

.. example:: basics/saving/progress

- Первый :godot:`ConfigFile` записывает значения и сохраняет файл, второй
  загружает его заново — так, как это будет при следующем запуске игры.
- Ключа ``gold`` в файле нет, и ``get_value()`` возвращает значение по умолчанию
  ``0``.

При первом запуске файла ещё нет, и ``load()`` вернёт ошибку. Это нормально:
просто начинайте с значений по умолчанию.

Для сложных данных — инвентаря, карты мира — используют JSON:
:godot:`JSON.stringify()` превращает словарь в строку, :godot:`JSON.parse_string()`
— обратно, а :godot:`FileAccess` записывает и читает строку из файла.

.. mistakes::

   - **Сохранение работает в редакторе, но не после экспорта.** Сохраняли в
     ``res://``. Для данных игрока — только ``user://``.
   - **Игра падает при первом запуске.** Файла ещё нет, а код использует
     прочитанные значения без проверки. Проверяйте результат ``load()`` и
     задавайте значения по умолчанию в ``get_value()``.
   - **Где лежит файл?** **Project → Open User Data Folder** открывает папку
     ``user://`` этого проекта.
   - **Старое сохранение мешает проверять.** Удалите файл из этой папки — игра
     начнёт с нуля.
